# 碎片交换

已在当前 Supabase 执行 `migrations/005_trades.sql`。其他部署在基础、认证及碎片管理迁移后运行 `python manage.py init-trades`。新增的交换、项目、预留、通知队列表全部开启 RLS，不向匿名数据库客户端开放。

## 使用流程

1. `/search-fragments` 的玩家记录点击「提出交换」，或在图鉴头像详情点击玩家／游戏账号，也可直接打开 `/trades`。图鉴链接会带入对方账号、对应式神和提供方向。
2. 选择自己的游戏账号及对方账号；对方账号支持按玩家名、游戏账号及服务器搜索。式神选项和搜索选择器只列出该方账号实际可提供的碎片，并显示扣除预留后的可用数量。填写双方各至少一项，数量不可超过可用量；提交及接受时服务端会再次检查。
3. 待接受阶段不预留；对方可在网站或 Discord 私信按钮接受／拒绝。发起人不能代对方接受。
4. 接受时重新检查双方可用数量并原子预留。图鉴与搜索显示扣除预留后的可用量；我的碎片同时显示库存总数、可用数和预留数。
5. 双方在游戏中实际完成后，各自在网站点击完成。只有双方都确认，系统才扣除各自交出的提供数量和已匹配的需求数量；不会把收到的碎片自动加入可提供清单。
6. 完成前任一方可以取消，包括一方已确认完成的情况；取消释放预留，不扣库存。双方都完成后的记录不能取消，避免自动恢复已交付的碎片。

同一库存上的申请接受、库存修改、取消及完成会串行锁定游戏账号。多个申请不能重复预留同一数量；人工覆盖及 OCR 保存不能低于预留数。完成与重复按钮请求不会重复扣除。接受后保留实际库存直到完成，不提前扣两次。

需求预留最多为接收账号目前尚未匹配的需求量；没有需求记录也可主动提出交换。完成时仅减少已预留的需求，不产生负数。新数量覆盖不改变交换项目；要换内容需取消重提。

`/trades` 可处理自己的待处理申请，或查看全站交换中。`/trade-records` 是独立的全站交换记录页，所有登录玩家可查看正在交换的记录；Admin 还可切换到已完成记录。每页 40 条，支持翻页，展示双方玩家、游戏账号、服务器、交换项目、数量、确认进度和更新时间。

已完成记录仅 Admin 可见，包括旧的我的交换列表与按记录 ID 查询接口；普通用户不能通过 URL 参数绕过。Admin 权限取自当前登录用户的实际角色，每次请求检查。待接受、已拒绝、已取消的申请仍仅当事人可见。全站及图鉴明细不公开 Discord ID 或私信内容。

## 单人可见通知

用户要求每条消息只有接收者看见，因此当前选择 Discord 私信：

```dotenv
DISCORD_TRADE_CHANNEL_ID=1504352387635216545
DISCORD_TRADE_MODE=dm
```

频道 ID 已写入本机 `.env`，但普通频道无法主动发送仅指定用户可见的消息，所以 **DM 模式不把交换消息发进此频道**，也不在私信失败后改发公开频道。

- 申请只通知被邀请方，含接受／拒绝按钮。
- 拒绝只通知发起方；接受后通知发起方已预留。
- 一方取消或确认，通知需要获知此状态的另一方。
- 双方最终完成，分别向各自发私信，两人不会共用会话。

私信关闭、Bot 离线或服务异常时，交换记录仍在网站可处理，通知状态会显示排队或失败。数据库 outbox 记录接收者，后台重试（最多 8 次，失败间隔至少 1 分钟）；当事人可在网站重试失败通知。发送成功后数据库确认丢失时，会检查最近消息的通知编号以降低重复通知；外部网络不能保证绝对只发送一次，重复通知也不会重复执行交换操作。按钮在 Bot 重启后仍可验证处理。

备用 `private_thread` 模式会在频道下给每个接收者分别建私密线程、只邀请该接收者，且管理线程者仍可能访问；当前未启用此模式。不能用线程冒充严格的「仅该用户可见」。

## Bot 指令与部署

现有 Bot 加载 `discord_trades` 扩展；本仓库 `discord_bot.py` 已加载它和 `discord_login`。Bot 与网站必须使用同一 Supabase 连接。`/fragments rarity:SSR name:不知火` 支持名字自动补全、繁简体，结果仅给指令使用者，数量排除已预留。

Render Web Service 运行 `python app.py`；Bot 是持续在线的另一个进程或 Worker。Bot 独立部署时配置 `WEBSITE_URL` 指向网站，并在该服务设置 `DISCORD_TRADE_MODE=dm` 及频道环境变量。本机 `.env` 不会上 Git，也不会自动变成 Render 环境变量。

```powershell
python -m unittest discover -s tests -p trades_postgres_checks.py
python -m unittest discover -s tests -p test_trade_bot.py
python tests/browser_trades.py
```

验证接受／拒绝权限、预留、取消、双方完成、重复请求、数量修改保护、竞争接受与单人私信路由。Bot 私信测试使用替身，不向真实玩家发送测试消息。
